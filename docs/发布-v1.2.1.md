## 2. 构建签名 Release

### 工具链（照这套来，别混用）

| 组件 | 版本 | 出处 |
|---|---|---|
| Gradle | 9.5.1 | `gradle/wrapper/gradle-wrapper.properties` 写死，`./gradlew` 自己下 |
| AGP | 9.2.1 | 根 `build.gradle` 里 `com.android.application` |
| JDK | **21** | `compileOptions` 为 `VERSION_21`；用 17 会在 `compileJava` 报 `release version 21 not supported` |
| Android SDK | Platform 36 + Build-Tools 36.x | `compileSdk/targetSdk 36`、`minSdk 26` |
| 依赖 | 仅 `io.github.libxposed:api:102.0.0`（compileOnly） | v1.2.1 已删 androidx 与全部 `R` 引用 |

`gradle.properties` 里指向 `/opt/android-sdk/aapt2bin/aapt2` 的覆盖已注释掉，普通机器直接构建；
只有在装有该二进制的编译沙箱里才临时加回：
`./gradlew -Pandroid.aapt2FromMavenOverride=/opt/android-sdk/aapt2bin/aapt2 :app:assembleRelease`。

### 命令

```bash
cd <仓库目录>
export JAVA_HOME=/path/to/jdk-21
export ANDROID_HOME=/path/to/android-sdk

# 签名信息只从环境变量读，仓库里没有口令；别名默认 wlmosv，key 口令默认同库口令
export TGAS_KEYSTORE=/path/to/your-release.jks     # 必须与 v1.1.0/v1.2.0 同一把 key
export TGAS_KEYSTORE_PASS='<库口令>'
export TGAS_KEY_ALIAS='wlmosv'
export TGAS_KEY_PASS='<别名口令>'

./gradlew --no-daemon clean :app:assembleRelease
APK=app/build/outputs/apk/release/app-release.apk

# 版本号核对
"$ANDROID_HOME/build-tools/36.0.0/aapt2" dump badging "$APK" | head -2
# 期望 package: name='io.github.wlmosv_png.tgautosign' versionCode='103' versionName='1.2.1'

# 签名指纹核对（关键）
"$ANDROID_HOME/build-tools/36.0.0/apksigner" verify --print-certs "$APK"
```

不设 `TGAS_KEYSTORE` / `TGAS_KEYSTORE_PASS` 也能构建，AGP 只打一条 warn，产物是**未签名**的，
需要自己 `apksigner sign`。口令一律走环境变量或本机 key 管理器，**不要**再写回 `build.gradle`
（v1.2.0 及更早提交里的明文口令建议 `keytool -storepasswd` / `-keypasswd` 轮换一次，换口令不换证书，
指纹仍然有效）。

### 必须匹配的签名证书（从 v1.2.0 正式包 APK Signing Block 提取）

    subject / issuer : C=CN, O=wlmosv, OU=TGAutoSign, CN=wlmosv
    serial           : 0705BF9BAA51FD1F
    validity         : 2026-09-07 21:53 UTC ~ 2054-01-23
    公钥             : RSA 2048
    SHA-256 指纹      : AF:55:24:CD:55:4A:E6:ED:E3:EC:27:47:C7:BE:D1:59:B0:9B:C4:F6:A4:32:44:A6:8B:46:22:E9:46:32:25:C8

`apksigner verify --print-certs app-release.apk` 得到的 SHA-256 digest 必须与上面完全一致，
否则老用户只能卸载重装（会丢签到目标）。证书 DER（公钥，可公开）备份：
`Download/TGAutoSign-v1.2.0-release-cert.der`；私钥 keystore 不在这台手机上。

## 3. 真机自测清单（v1.2.1 真实菜单）

模块的全部管理入口都在 Telegram 里发消息 `/jmb` 弹出的对话框：`📋 目标列表`、`➕ 添加目标`、`🗑 删除目标`、
`🚀 立即签到`、`📄 运行日志`、`⚙️ 设置`、`🔄 检查更新`、`📤 导出配置`、`📥 导入配置`。
**没有独立管理 App，也没有桌面小组件**——那些是 v2 时代的不可达代码，已在 `1e21104` 删除，找不到它们是预期的。

1. v1.2.0 设备上**覆盖安装**（不要先卸载），`/jmb → 📋 目标列表` 确认目标与「已签」状态仍在。
2. `/jmb → 🔄 检查更新` → 应显示「已是最新 v1.2.1」。
3. 装有 v1.2.0 的设备上检查更新 → 应提示发现 1.2.1 并出现 `⬇️ 下载 v1.2.1 安装包`；点它应写入系统「下载」并拉起系统安装器完成覆盖安装（这一步同时反证签名指纹正确）。
4. 开机后台静默检查有 12 小时冷却，`/jmb` 里的手动检查无视冷却；测试时先想到这条。
5. `/jmb → 📤 导出配置` → 回报 json 文件名，格式 `TGAutoSign-config-1.2.1-<yyyyMMdd-HHmmss>.json`，同时存在于系统「下载」和 `Android/data/org.telegram.messenger/files/tgautosign/`。
6. 清数据或换账号后 `/jmb → 📥 导入配置` → 读到最新导出文件，只合并、不清空。
7. 到点签到回归：目标 bot 正常收到指令，成功即停；已签目标显示「已签」。
8. 飞行模式下点检查更新 → 只报检查失败，签到主流程不受影响，无崩溃。
9. `/jmb → 📄 运行日志` 首行应能看到 `=== TGAutoSign 模块 v1.2.1 (jmb界面版) 已加载 ===`。
